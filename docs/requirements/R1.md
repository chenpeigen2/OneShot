## 1. 背景与问题陈述

### 1.1 为什么是它

OneShot 的运行依赖一条长长的环境链：本地 PocketBase 引擎二进制（`.oneshot/pocketbase`）→ 引擎进程 → 超管凭据（环境变量或 `.env`）→ 合法的 `oneshot.config.ts` → 已编译的 hooks（`pb_hooks/`）→ 已发布的快照（`oneshot_meta`）。任何一环断裂，用户看到的都只是某条命令的一个报错尾巴（"连接失败"、"需要超管账号"、"当前目录没有 oneshot.config.ts"），需要逐环排查。对一个以"自托管、一条命令搞定"为卖点的框架，缺一个把整条链一次性照一遍的工具。

典型故障场景（均来自现有架构的真实断点）：

1. `oneshot dev` 报连接失败——是引擎没装？引擎没启动？还是 baseUrl 写错？三者报错表象相同。
2. 凭据环境变量拼写错误 / `.env` 未加载——publish 在交互提示处挂起（`resolveSuperuser` 会等待 stdin），CI 里表现为超时而非明确报错。
3. manifest 被手工改坏（非法字段名、handler 路径不存在）——直到 publish 中途才失败，此时可能已写入部分 collection。
4. 本地 manifest 与 PB 里已发布版本漂移（改了 config 忘了 publish，或改了 PB Admin UI）——没有任何命令能看到这个差异。
5. 服务从 manifest 移除后 `pb_hooks/` 留下孤儿产物（`<svc>.pb.js`），下次引擎冷启动仍会加载已废弃的 hook。
6. 长期运行后 `.oneshot/`（引擎 + 日志）、`pb_data/`、备份文件悄悄吃满磁盘。

### 1.2 候选对比（为什么不是别的）

| 候选 | 结论 | 理由 |
| --- | --- | --- |
| (a) 控制台记录浏览增强 | 否 | 纯 React UI 变更。现有 e2e 框架是 HTTP/进程级（fetch + spawnSync），无浏览器断言能力，UI 行为无法在 `tests/suites/*.test.mjs` 模式下验收；PB 原生 filter/sort 能力反而已被 core 套件覆盖。验收会退化成"重新断言 PB 本来就会的东西"。 |
| (b) 备份自动调度（cronAdd） | 否 | e2e 要等 cron 真实触发（最快 1 分钟/次，套件超时 180s，脆弱）；退而断言编译产物文件内容则是弱验收。且 README 已记录 JSVM 可靠面的多个坑，cronAdd 属于未实测区域，风险与改动面（DSL 扩展 + hooks 编译器 + 生命周期）超出单迭代。 |
| (c) **`oneshot doctor`** | **是** | 纯增量 CLI 命令：不触碰 publish/provisioner/codegen/console 任何路径，天然不威胁既有 55 项断言；其验收形态（spawnSync 跑 CLI + 断言退出码/stdout + HTTP 探测 + 文件系统检查）与现有 harness 模式 1:1 对齐（env-collections 套件已有 execFileSync 失败断言先例，run-e2e.mjs 用 spawnSync 跑 publish）。 |
| (d) 生成客户端文件上传辅助 | 否 | 双语言（TS + Dart）生成器同时改动，需新增含 file 字段的 fixture；e2e 只能做生成文件内容断言（真要跑生成的 TS 客户端需引入新的 TS 编译运行管道）。改动面最大、验收路径最弱。 |

### 1.3 一句话定位

`oneshot doctor` = 在一条非交互命令里，对"引擎 → 网络 → 凭据 → manifest → 发布一致性 → hooks 卫生 → 磁盘"七环做体检，每环给出 `ok / warn / fail / skip` 与可行动的修复提示，`--json` 供 CI 消费。

## 2. 用户故事

1. 作为**自托管用户**，我在 `oneshot dev` 连不上时运行 `oneshot doctor`，以便 30 秒内知道断在哪一环（引擎没装 / 进程没起 / 凭据错 / 地址错），而不是逐条命令试错。
2. 作为**CI 维护者**，我在流水线里跑 `oneshot doctor --json` 并依赖退出码，以便在 publish 之前拦截坏 manifest 与不可达实例，拿到机器可读的诊断报告。
3. 作为**项目所有者**，我改完 `oneshot.config.ts` 但不确定是否已发布，运行 `oneshot doctor`，以便通过快照 hash 对比发现本地与 PB 的漂移，被告知"重新 publish"。
4. 作为**运维者**，我运行 `oneshot doctor`，以便发现 `pb_hooks/` 里不再属于任何服务的孤儿 hooks 产物，以及 `.oneshot/`、`pb_data/` 的磁盘占用。

## 3. 功能需求

约定：检查项状态取值 `ok` / `warn` / `fail` / `skip`。`fail` 使退出码为 1；`warn` 不影响退出码；`skip` 表示因前置失败未执行。除 FR-1 的 `--email/--password` 外，doctor **绝不读 stdin**（FR-11）。

- **FR-1 命令签名**：`oneshot doctor [--config <path>] [--url <url>] [--email <email>] [--password <password>] [--hooks-dir <dir>] [--engine <path>] [--json]`。
  - 目标地址解析顺序：`--url` > `ONESHOT_PB_URL` > manifest 的 `baseUrl`；
  - 凭据解析顺序：`--email/--password` > `ONESHOT_SUPERUSER_EMAIL/PASSWORD`（含项目根 `.env`，复用现有 `loadDotEnv`）；
  - manifest 位置：`--config` > 现有 `findConfig` 的 cwd 查找链；
  - hooks 目录：`--hooks-dir` > `<项目根>/pb_hooks`（与 publish 默认值一致）；
  - 引擎二进制：`--engine` > `enginePaths(cwd).bin`（`<cwd>/.oneshot/pocketbase`）。

- **FR-2 检查项 `config`（manifest）**：执行 `loadManifest` + `validateConfig`（core 已导出，内含 hooks/handler 文件存在性检查）。失败 → `fail` 并附错误消息，且 FR-4/5/6 项标 `skip`。

- **FR-3 检查项 `engine`（本地引擎）**：对解析出的引擎二进制：文件不存在 → `warn`（detail 提示 `oneshot engine install`，本地引擎缺失不影响连接远端实例）；文件存在但执行 `--version` 非零退出 → `fail`；成功 → `ok` 且 detail 携带版本号字符串（如 `v0.40.6`）。

- **FR-4 检查项 `connectivity`（连通性）**：`GET {baseUrl}/api/health`（2 秒超时）。非 200 / 网络错误 → `fail`，且 FR-5/6 标 `skip`；成功 → `ok`。

- **FR-5 检查项 `credentials`（凭据）**：用解析到的邮箱/密码调 `_superusers/auth-with-password`。凭据未提供 → `warn`（detail 列出所查的环境变量名，绝不交互等待）；登录失败 → `fail`；成功 → `ok`（token 仅内存使用，不落盘、不打印）。

- **FR-6 检查项 `snapshot`（发布一致性/漂移）**：前置 = FR-4、FR-5 均 ok。用 core 导出的 `buildSnapshot(config)` + `snapshotHash(...)` 计算本地 hash，与 PB `oneshot_meta` 中 `project = {config.name}` 的最新记录的 `snapshot.hash` 对比：无记录 → `warn`（"尚未发布"）；hash 一致 → `ok`（detail 含 hash）；不一致 → `warn`（"本地 manifest 与已发布版本存在漂移，建议 oneshot publish"，detail 含两侧 hash 前 8 位）。

- **FR-7 检查项 `hooks`（孤儿产物）**：扫描 FR-1 解析的 hooks 目录下匹配 `*.pb.js` 的文件，解析所属服务名：去掉 `.pb.js` / `.user.pb.js` 后缀后取第一个 `.` 之前的部分（覆盖 `<svc>.pb.js`、`<svc>.user.pb.js`、`<svc>.<coll>.user.pb.js` 三种产物命名）。服务名不在 manifest `services` 名单 → 计为孤儿。存在孤儿 → `warn` 并列出文件名（detail 提示确认后可手工删除）；目录不存在 → `ok`（"尚未发布过"）；无孤儿 → `ok`。

- **FR-8 检查项 `disk`（磁盘占用）**：汇总三个路径的递归字节数——`enginePaths(cwd).root`（`.oneshot/`：引擎+日志）、`enginePaths(cwd).dataDir`（`pb_data/`）、FR-1 的 hooks 目录。缺失路径计 0。总量 > 1 GB → `warn`，否则 `ok`。本项纯信息，永不 `fail`。

- **FR-9 输出协议**：
  - 默认（人类可读）：逐项一行 `✅/⚠️/❌ [检查项] 详情`，`skip` 用 `⏭`；摘要行 `诊断完成：N 项 ok · M 项 warn · K 项 fail` 与修复提示写 **stderr**；
  - `--json`：stdout 输出**单个 JSON 文档**（stderr 仍可有人类摘要）：
    ```json
    {
      "project": "todo",
      "target": "http://127.0.0.1:8090",
      "ok": true,
      "checks": [
        { "id": "config", "status": "ok", "detail": "…", "orphans": [], "version": "v0.40.6", "hash": "…" }
      ]
    }
    ```
    `checks` 按固定顺序：`config, engine, connectivity, credentials, snapshot, hooks, disk`；每项必有 `id/status/detail`，附加字段按项可选（`orphans`/`version`/`hash`/`bytes`）。stdout 除该 JSON 外无其他内容（保证 e2e 可 `JSON.parse(stdout)`）。

- **FR-10 退出码**：存在任一 `fail` → 1；否则 0（`warn`/`skip` 均为 0）。`--json` 不改变退出码语义。

- **FR-11 非交互保证**：任何分支不得读取 stdin。凭据缺失走 FR-5 的 `warn` 路径，使命令在 CI / `spawnSync` 管道中永不挂起。

- **FR-12 零回归**：doctor 为纯新增命令；不修改 publish/gen/dev/console/superuser 的任何行为，不修改 `@oneshot/core` 导出面（只新增 import）。

## 4. 验收标准

新增套件 `tests/suites/doctor.test.mjs`，追加进 `tests/run-e2e.mjs` 的套件列表**末尾**（该套件会临时写孤儿文件并自恢复，放最后避免干扰）。套件可用的既有注入：`TEST_CLI`、`TEST_FIXTURE_DIR`、`TEST_MAIN_HOOKS_DIR`、`TEST_PB`；runner 需**新增一行**注入 `TEST_PB_BIN`（run-e2e.mjs 已解析出的 `pbBin` 绝对路径）。spawnSync 运行 CLI 时环境变量带上 `ONESHOT_PB_URL` / `ONESHOT_SUPERUSER_EMAIL` / `ONESHOT_SUPERUSER_PASSWORD`（与 runner 跑 publish 的方式一致）。

每条 AC 标注对应的可写 e2e 断言（`assert(name, cond)`）。

- **AC-1 正常路径全绿**：套件开头对 fixture 执行一次 `publish --no-gen --hooks-dir $TEST_MAIN_HOOKS_DIR`（保证快照新鲜，模式同 env-collections 套件），然后 `spawnSync` 运行 `doctor --hooks-dir $TEST_MAIN_HOOKS_DIR --engine $TEST_PB_BIN`。
  - 断言：进程退出码 === 0；
  - 断言：`--json` 的 stdout 可 `JSON.parse`，且 `config/engine/connectivity/credentials/snapshot/hooks` 六项 status 全为 `ok`。

- **AC-2 快照一致性**：AC-1 的 JSON 中 `snapshot` 项 `status === 'ok'` 且 `hash` 字段与超管 token 查询 `GET /api/collections/oneshot_meta/records?filter=project="e2e-fixture"` 所得记录的 `snapshot.hash` **字符串相等**。
  - 断言：两侧 hash 相等。

- **AC-3 漂移告警**：将 fixture 的 `oneshot.config.ts` 内容做一次语义级修改（如把服务 `title: '任务'` 改为 `title: '任务x'`），**不重新发布**，再跑 `doctor`。
  - 断言：`snapshot.status === 'warn'` 且 detail 含"漂移"字样；
  - 断言：整体退出码仍为 0（warn 不影响退出码，验证 FR-10）；
  - 收尾：用缓存的原文件内容**恢复** `oneshot.config.ts`（套件内置 try/finally 语义，作者自行保证）。

- **AC-4 引擎缺失降级为 warn**：不带 `--engine` 且在无 `.oneshot/` 的临时 cwd 下运行。
  - 断言：`engine.status === 'warn'` 且退出码仍为 0（FR-3 的 warn 路径）。

- **AC-5 不可达实例 fail**：`doctor --url http://127.0.0.1:9`（discard 端口）。
  - 断言：`connectivity.status === 'fail'` 且 `credentials/snapshot` 两项 `status === 'skip'`；
  - 断言：退出码 === 1。

- **AC-6 错误凭据 fail**：以 `ONESHOT_SUPERUSER_PASSWORD=definitely-wrong` 运行（目标地址正常）。
  - 断言：`credentials.status === 'fail'` 且 `snapshot.status === 'skip'`；退出码 === 1。

- **AC-7 坏 manifest fail**：复制 fixtures 到 `tests/.tmp/bad-project/`，将其 config 中加一个非法字段名（`Bad Name`，validateConfig 会拒绝，同 manifest 套件的先例），`doctor --config` 指向它。
  - 断言：`config.status === 'fail'` 且 detail 含"非法"；`connectivity/credentials/snapshot` 均 `skip`；退出码 === 1。

- **AC-8 孤儿 hooks 告警与恢复**：向 `$TEST_MAIN_HOOKS_DIR` 写入 `ghost_orphan.user.pb.js`（一个字节的占位内容即可；主实例不热加载 hooks 目录，无运行时副作用；文件名前缀避开全部真实服务名）。
  - 断言：`hooks.status === 'warn'` 且 `orphans` 数组包含该文件名；
  - 清理：删除该文件后再跑一次 `doctor`；
  - 断言：`hooks.status === 'ok'`。

- **AC-9 引擎版本可见**：AC-1 的 JSON 中 `engine` 项 `version` 字段为非空字符串且以 `v` 开头。
  - 断言：`/^v\d/` 匹配。

- **AC-10 磁盘信息项**：AC-1 的 JSON 中 `disk` 项存在 `bytes` 数值字段 ≥ 0 且 status ∈ {ok, warn}。
  - 断言：字段存在且类型正确。

- **AC-11 非交互不挂起**：以上所有 spawnSync 调用均在套件 180 秒超时内自然返回（凭据缺失场景 AC-4 亦不等待 stdin）。
  - 断言：AC-1~AC-10 全部通过即隐式覆盖；无需独立断言。

- **AC-12 零回归**：`pnpm test:e2e` 全量通过；既有 5 套件 55 项断言逐字未动，新增套件约 12–14 项断言（总断言约 67–69），README 中相应计数与套件列表同步更新。
  - 断言：runner 总结行 `6/6 套件通过`。

## 5. 非目标（本迭代明确不做）

1. **不做 `--fix` 自动修复**：孤儿文件、磁盘清理、漂移重发布都只给提示命令，不代执行（避免诊断工具自带破坏性）。
2. **不检查远端 PB 版本与本地引擎版本的一致性**：`/api/health` 不返回版本号，远端版本探测无稳定公开 API，留待后续。
3. **不做交互式凭据输入**：doctor 永不读 stdin（区别于 publish 的 `resolveSuperuser` 交互路径）。
4. **不改动控制台**：不在 Web 控制台加"诊断"面板（UI 验收超出当前 e2e 框架能力，见 1.2 对候选 a 的分析）。
5. **不做备份调度 / 记录浏览增强 / 文件上传辅助**：三个候选均落选本迭代（见 1.2），留待后续迭代重新评估。
6. **不做 Windows 专项适配**：沿用 `engine.ts` 既有的 `win32` 后缀判断，不新增平台分支。
7. **不持久化诊断历史**：不写任何报告文件，stdout/stderr 即全部产物。

### 实现注意（坑位提示）
1. `--json` 时 stdout 必须只有单个 JSON 文档——现有 CLI 习惯把日志写 stderr（见 `doPublish`），doctor 的人类可读输出延续写 stderr。
2. `snapshotHash(buildSnapshot(config))` 是纯本地计算，不需要网络；对比目标在 PB 侧 `oneshot_meta`，需要超管 token（依赖 FR-5 成功）。
3. 健康检查用 `AbortSignal.timeout(2000)`，与 `tests/run-e2e.mjs` 的 `waitHealth` 风格一致。
4. 孤儿检测不要把非 `*.pb.js` 文件（如 `.gitkeep`）算进去；目录不存在视为 ok 而非错误。
5. doctor 套件对 fixture `oneshot.config.ts` 的修改必须用"读原内容 → 写改版 → 跑 doctor → 写回原内容"包络，且该套件排在最后，把污染面锁死。
